# Atlas portfolio activation

## Outcome

Organize the current live Atlas queue into the full project-management model
without changing the meaning of source actions or creating decorative records.

## Requirements

1. Restore the four long-lived Four-Lane anchors required by the approved
   weekly protocol; preserve their user-only ownership and evidence.
2. Create a bounded set of outcome projects from current multi-action work.
3. Create strategic initiatives only where at least two real projects exist.
4. Add milestones only where actions map to distinct verifiable stages.
5. Assign currently executable, near-term work to one workspace cycle; exclude
   dormant approvals, far-future work, and user-only actions.
6. Create useful contextual action views for multi-action projects.
7. Create one workspace portfolio document whose `ATLAS-N` references produce
   automatic backlinks, plus concise project updates for materially active
   projects.
8. Create reusable portfolio Insights and one dashboard.
9. Preserve source action status, priority, owners, due date, approval state,
   work mode, evidence, and completion timestamps except for the explicitly
   restored standing anchors.
10. Every record is idempotent, auditable, reversible through archive/status
    lifecycle, and verified with pgTAP/readback.

## Exclusions

- No fake releases, pipelines, comments, notifications, or filler projects.
- No external messages, payments, bookings, submissions, or portal changes.
- No automatic activation of paused schedulers.
- No ownership, approval, priority, or due-date rewrites.
